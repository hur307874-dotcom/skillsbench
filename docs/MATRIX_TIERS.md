## 0. 三档总览

| 档位 | run 数 | 并发假设 | 单 run 均值 | 墙钟估算 | 用途 |
|------|--------|---------|------------|---------|------|
| **quick** | 48 | 10 | ~8 min | **~40–60 min** | 分诊：排除明显没用的 Skill |
| **standard（压缩完整档）** | ~320 | 16–20 | ~7 min（超时掐尾后） | **~3–4 h** | 确诊：中介链 + 归因 + 闭环全保留 |
| **full（原版完整档）** | ~700 | 16–20 | ~8 min | **过夜（8–12 h）** | 加厚：heldout 复验 + 梯度/跨厂商补强 |

> 单 run 时长为**估算值**（D1 2–5 min / D2 5–15 min / D3 10–30 min 加权）。
> 必须在 3 实例纵切 + B0 探活后用实测均值回校本表全部时间与成本数字。

## 1. quick 档（matrix/quick.yaml）— 当前执行

| 维度 | 配置 | 理由 |
|------|------|------|
| 臂 | **A0 + A1f** | 信息密度最高的一对：基线 vs 强制注入，直接回答"有没有用、代价多少" |
| 任务 | 12（D1/D2/D3 各 4，D3 可降为 2） | 计划砍单线允许的规模；覆盖难度分层 |
| 重复 | n=2 | 48 run 预算硬约束 |
| 超时 | 单 run 硬超时 12 min | 掐 D3 长尾，并发槽位周转率翻倍 |
| 模型 | 迭代用 Haiku 档快模型；结论性数字用目标模型 | 快模型单 run 3–5 min，日常调试半小时出结果 |
| run 数 | 12 × 2 臂 × 2 = **48** | 1 小时 ÷ 8 min × 并发 10 ≈ 60–75 run 预算内 |
| 附加 | 行为信号检测器照跑（纯函数、不花 run） | 指令级线索不丢（方向性） |

**quick 档回答**：这个 Skill 值不值得深入测（增益方向 + token 成本量级）。

**quick 档缺失**（报告必须声明）：
- 无 A1（自主触发）→ 测出的是**内容上限**，真实收益 ≤ 此值；
- 无 A0p（placebo）→ 无法排除注意力效应；
- 无逐条消融 → 无指令级三分法；
- 无 heldout、无模型梯度、无跨厂商；
- n=2 → 无 CI，只报方向 + 逐任务符号（12 个任务中 A1f−A0 为正的个数）。

### 1.1 quick-lite（真·最简）与序贯分诊

quick 之下还有一档：**A0+A1f × 6 任务（每难度 2）× n=1 = 12 run，~10–15 分钟**。
不可再砍项只有两个：A0 基线（无基线则"有没有用"无从谈起）和任务数 ≥6
（再少分不清"Skill 没用"与"卷子出坏了"）。

12 run 下仍有效的信号：① 成本指标（token/轮次是连续变量，+xx% 级爆炸 6 对配对
即可见）；② 行为信号检测器（不调 LLM、不花 run）。变弱的是通过率维度
（n=1 无方差概念，只剩 6 对配对符号）。

**quick-lite 的合法结论只有一种句式**："值得 / 不值得花 3–4 小时确诊"。
出局结论必须写明依据（6 对配对 + 成本指标），不能表述为"证明无效"——
它证明的是"在本任务池上看不到值得深测的信号"。

**推荐用法：序贯分诊，而非固定档位**——

```
先跑 quick-lite 12 run
  ├─ 增益明显为正或成本明显异常 → 直接升级 standard（跳过 48）
  ├─ 明显零增益且成本正常 → 出局，出 quick 报告（总花费 ~15 分钟）
  └─ 信号模糊 → 补跑至 48（+6 任务、n=2）再判
```

对"明显没用"的 Skill（按 SWE-Skills-Bench 39/49 的比例这是大多数）15 分钟结案，
只有模棱两可者花满 1 小时——平均成本低于固定 48 run。
**红线：任何评测性结论不得低于 12 run**；6 run 是 B1.5 冒烟的规模，只查坑不评测。

## 2. standard 档（matrix/standard.yaml）— 当前执行（确诊）

| 模块 | 配置 | run 数 |
|------|------|--------|
| 主矩阵 | A0/A0p/A1/A1f × 12 任务 × n=2 | 96 |
| A1-noref | 12 × n=2（H3 渐进披露，tdd 类有引用文件的 Skill 才启用） | 24 |
| 逐条消融 | 7 指令 × verify_tasks(~4) × n=2（二元行为信号 n≈14 功效仍够） | 56 |
| A2 v2 闭环 | 12 × n=2 | 24 |
| 模型梯度（H4） | 3 档 × A0/A1f × dev 6 × n=2 | 72 |
| codex 跨厂商 | A0/A1f × 6 × n=2 | 24 |
| 第二 Skill 通用性 | A0/A1f × 8 × n=2 | 32 |
| 埋针校准 | 归因器 ground truth 小矩阵 | ~20 |
| **合计** | | **~320（上限 ~350）** |

**保留的骨架（不可砍，继承 PLAN §11）**：init 接入流程 / 主矩阵 / A1-noref / 中介链消融 /
难度分层 / 归因器校准 / heldout 终验 / 被证伪假设专节 / AI 使用记录。

**压缩代价（诚实标注）**：
- n=2 → 彻底告别 CI（与既定口径一致，不算降级）；
- heldout 8→4：从弱证据降为轶事证据，措辞用"方向一致（x/4）"；
- H4 每格 ~12 run：方向性证据，不讲成结论；
- 12 任务族覆盖减半，"不过拟合"论证弱一分。

**物理下限**：再压（<200 run）消融臂每指令 <8 观测、heldout 名存实亡，
中介链 + heldout 终验两个招牌失效——**~300 run 是确诊档的下限**。

## 4. 执行顺序与门禁

```
B0  探活：列模型、tool use 流式、实测中转站并发天花板（连发 10 个看 429）
    → 校准"并发假设"列
A3  3 实例纵切：实测单 run 时长与 token 成本 → 回校准三档预算表
B1.5 全臂冒烟（~20 run，~1h，不可省）：查坑不查结论——
    A0 确实没加载 / A1-noref 确实读不到引用文件 / 判分合理 / trace 完整 / 成本符合预估
quick 档 → 分诊决策点：
    A1f−A0 方向为正或有显著成本异常 → 进 standard 档
    零增益且成本无异常 → 直接出 quick 报告（该 Skill 分诊为"不值得深测"）
standard 档（~3–4h）→ 确诊报告 + v2 闭环
full 档（可选，过夜）→ heldout/梯度加厚
```

## 5. 成本与超支熔断

- quick 档单次成本预估：48 run ×（实测单 run token × 中转站单价），B0 后填入；
- standard 档预算上限：待实测校准后设定，**超支 80% 触发熔断**，按砍单线
  （process_judge → codex → 梯度缩两档 → 第二 Skill 缩减）顺序降载；
- 缓存幂等：同配置 run 命中缓存零成本；断点续跑保证中断不浪费已烧的钱。

## 6. 任务集来源（与三档正交）

| 来源 | 状态 | 护栏 |
|------|------|------|
| 内置默认集（12/24 实例） | 主用 | 与任何 Skill 无关、不为被评 Skill 定做；校验器四关 |
| 用户自带代码库 | 支持 | LLM 只做适配性审查/改造建议/测试草稿；**四关硬校验必须机器过**；过 Pilot Gate 校准难度；与内置集分开报告 |
| LLM 盲生成任务集 | 砍单线 | 三护栏：生成器看不到被评 SKILL.md（盲生成）/ 校验器打回循环 / 生成器偏差校准（tdd 试金石量化偏差）；**heldout 永远人写人审** |

底层原则：**LLM 可以帮忙造卷子，但永远不能看考生答案；阅卷必须机器做。**
跨 Skill 可比性靠"共享任务池 + manifest 按 F-ID 自动选集（verify_tasks）"保证，
不做各自独立的任务集。

## 7. 落地状态与校准实录（2026-09-24）

**已实体化**：`matrix/quick-lite.yaml` / `quick.yaml` / `standard.yaml` / `full.yaml`
四个预设 + 展开器（`backend/orchestrator/matrix.py`）+ dry-run 端到端管线
（`backend/orchestrator/dryrun.py`，mock agent + **真实 pytest 判分**）。
dry-run 已验证全链路：展开 → 执行 → 判分 → 汇总（runs.jsonl + summary.md）。

**首个真实 run（B0 探活，results/probe-d1-A0-r2/）**：d1-typo-01 × A0 × claude CLI
默认模型（opus-5，中转站）：5 turns / API 36s / **$0.53** / 隐藏测试 2/2 通过。
校准发现三条，直接影响档位选择：

1. **D1 单 run 远快于原估**（36s vs 估 3.5min）——quick 档 48 run 的时间预算有富余，
   D2/D3 待纵切实测后回校；
2. **成本由 cache 创建主导**（单 run cache_creation ~53k token ≈ $0.5/opus）——
   trivial run 也不便宜，run 数仍是成本主控变量；
3. **当前中转站令牌只放行 claude-opus-5**（haiku / sonnet 均 403）——
   quick 档"haiku 快模型压成本"路线与 H4 三档梯度**在当前令牌下不可行**；
   要么换多模型令牌，要么梯度节整体后移。另：docker daemon 不可用，
   沙箱暂以临时目录代替，正式矩阵开跑前必须恢复容器隔离（PLAN A0 阻塞仍在）。

**最终档位决策门（未定，待实验）**：补齐任务集（≥12 实例）后跑 3 实例纵切
（D1/D2/D3 各 1 × A0/A1f × opus），实测三档单 run 时长与成本，回校 §0 预算表，
再定默认执行档（quick 48 或 quick-lite 12 + 序贯）。在此之前默认从 quick-lite 进。
