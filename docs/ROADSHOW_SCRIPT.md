# 路演逐字稿（防线版 12 页 · 总时长约 7 分钟）
> 用法：黑体是逐字口播（照着念就行）；【锚点】是这页每个数字的出处，评委追问"这数哪来的"时翻这里；【接招】是评委最可能的刁问与应答。
> 总纪律：判词带括号，数字有出处，"我不知道"比"我瞎猜的"值钱。

---

## S1 封面（30 秒）

**口播**：
"写一个 Skill 只要十分钟，判断它有没有用，行业靠'俺寻思'。三周时间，我建了一套评测与优化体系——127 个批次、2455 个可控实验，任务池 58 题，18 道合成加 40 道真实 issue。今天讲三样：这台机器怎么判分、它怎么防止误判、以及它怎么从判分走到开处方。"

【锚点】127 批/2455 run：results/ 全量 runs.jsonl 现算（10-10）；58 题池：pool_info() 快照。

---

## S2 痛点（40 秒）

**口播**：
"题目说得很白：判断 Skill 有效性靠截图和感觉。我把痛点拆成三个真问题。第一，模型升级了，旧 Skill 还有效吗——没有复测机制，有效性靠记忆。第二，成功率涨了，Token 是不是翻了三倍——没有成本披露，增益和代价不同框。第三，没效果是 Skill 不行还是考卷不行——没有仪器自检。注意第三个问题最要命：考卷失效时，'零增益'是冤案。这三个痛点，对应我系统里的三个设计：复测按钮、成本比强制披露、池天花板检测。"

【锚点】三个设计均为产品现役功能（eval_skill 复测按钮/成本比字段/天花板检测）。
【接招】"成本比怎么算？"→ 开卷臂 output tokens ÷ 裸考臂，配对同题平均。

---

## S3 判据（30 秒，语速放慢，全场核心）

**口播**：
"先给结论。Skill 要么递答案，要么收仪式税——界限只有一个：内容在不在模型的先验里。模型本来就会的，读了只剩仪式和账单；本来不会的，读了才是答案。三个证据：SkillsBench 实测 49 个公开 Skill，39 个零增益；医疗协议实验，补训练缺席知识，+51.9 个百分点；我自己的三族虚构约定实验，安慰剂校正后 +0.36 到 +0.68。三方同向。接下来十五分钟，就是我怎么用 2455 个实验把这句话钉死的。"

【锚点】39/49：SkillsBench 论文公开数据（49 公开 Skill 39 零增益）；+51.9pp：医疗协议公开实验；+0.36~0.68：poolv3d 三批 runs.jsonl（S9 详解）。
【接招】"先验你怎么知道？"→ 无法直接探知，所以用虚构约定构造"物理上不在先验"的知识（S9）；用高星 Skill 实测"在先验"的表现（S7）。

---

## S4 判分机制（60 秒）

**口播**：
"先说分是怎么判的，这是一切的地基。一个 run 的一生：带 bug 的考卷进一次性容器，agent 裸考或读文档双臂做题，宿主机跑隐藏测试出分，全程录像留证据。五个设计，每个都有出处：一次性容器——只挂考卷和 Skill 两个目录，答案物理不可达，这借的是 Inspect 和 Terminal-Bench 的沙箱架构；双臂注入，--no-skills 对 --append-system-prompt，题目要求的消融；机械判分，f2p 必须过、p2p 不许挂，借自 SWE-bench；全事件留痕，trace.json，题目原文要求；渠道死二分，usage 等于零是基建失败，剔除补跑，这是实战教训。为什么全程零 LLM 判分？MT-Bench 那篇论文实测 LLM 判官四大偏差，其中冗长偏差会定向偏爱输出更长的 Skill 臂——用 LLM 判分，我测的是判官的口味，不是模型的能力。"

【锚点】容器：docker/pi-dis-provider.ts + 51 run 零越界审计（C7 批次）；tests 不进容器：runner 挂载设计；四大偏差：Judging LLM-as-a-Judge (Zheng et al. 2023)。
【接招】"agent 专门针对测试写答案怎么办？"→ tests 物理不在容器里，它想看都看不到；判分和答卷物理分居。

## S5 流水线（45 秒）

**口播**：
"一个 Skill 进来，过六站。预检——渠道 down 熔断，一个 run 都不烧。冒烟 6 个 run——先验证仪器，再相信读数。分诊 12 个 run——配对符号乘成本比，廉价杀掉 80%，因为 SkillsBench 实测 80% 公开 Skill 零增益，大多数废物不值得烧大钱。天花板检测——分诊零信号但裸考全满分时，'出局'罪名不成立，题目原文说'过于简单的 Skill 会让归因无从下手'，所以系统自动换带头难题进决定性模式。复测确诊——安慰剂臂排除长度效应，医学 RCT 对照思想。最后，弊端定位、改进、再验证——从判分到开处方。"

【锚点】六站全部现役（eval_skill 状态机）；天花板判据 A0≥0.95 占比 >2/3（ceiling_stats 实测值 5/6）；带头题定义 [0.3,0.7]（页底术语注）。
【接招】"为什么是漏斗？"→ run 成本 0.5~1 分钟一个，确诊批是定向的 4v4+，分诊 12 run 杀掉 80% 候选最省钱。

---

## S6 三道防线（90 秒，75% 时间点）

**口播**：
"评测系统最大的风险不是测不准，是把错的写成对的。三种最常见的误判来源，各配一道防线。第一道，任务效度门：考卷先过四道机器生死门——标准答案必过、错解必负、白卷必挂、结构完整。首版 6 道题毙掉 4 道——死跑都能拿满分的题，不配进考场。第二道，渠道健康协议：基建失败和能力失败物理分列，usage 等于零的死跑剔除补跑——曾经有两批 45 个 run 全是渠道死尸，差点写成'模型能力归零'。第三道，天花板检测：'零增益'和'池子测不出'是两种东西——一个高星 Skill 分诊 0/6，但 6 道题裸考全满分，系统拒绝冤判，换带头题复判，裸考 4/4 满分、读文档 0.42，现形。这三道防线，不是设计出来的，是长出来的——每一条都对应一次真实事故。"

【锚点】6 毙 4：pool-v2 初版四关校验记录；45：渠道混淆事件两批计数；4/4 vs 0.42：decisive-sysdbg runs.jsonl（n=4，判词自带"幅度需加厚"）。
【接招】"防线都是打脸的赔偿？"→ 一句带过："对，每条规矩后面都有一次翻车，报告的被证伪假设节全记着。"然后立刻往前走——不在失败故事上停留。

## S7 仪式税现形（75 秒，全场记忆点）

**口播**：
"obra/superpowers，二十九万七千星——GitHub 顶流仓库。它的 brainstorming Skill，开篇就是命令：任何创造性工作前，必须先头脑风暴。我们的实测：裸考 10 个有效 run，对 9 题；读了文档，11 个只对 4 题——decisive-negative。账单更狠：成本比五点零七倍。逐题看，mutable 题裸考 4 个满分，读了文档 4 个里 3 个零分。它不是在帮模型思考，是在让模型证明自己思考过——证明费五倍，思考质量还下降。弊端定位排出的罪魁，就是那条'必须前置'规则。同仓库的 systematic-debugging 是同款死因，trace 级实锤：agent 严格走完四阶段仪式，写了篇漂亮的根因分析，自信宣布 All pass——隐藏测试，0 比 3。流程给了它'我验证过了'的底气，没给它'验证得对不对'的能力。"

【锚点】297,832 星：2026-10-12 GitHub API 实测；9/10 vs 4/11、×5.07、mutable 0,0,0,1.0：evaldecisive-brainstorming-1006-1836 runs.jsonl（n=10/11，判词自带"幅度需加厚"）；弊端榜首：analysis.json；"All pass."→0/3：sysdbg 0 分 run trace。
【接招】"n 还是不大？"→"对，所以判词自带括号'幅度需加厚'——方向有 21 个 run 加 trace 机制证据，幅度我保留。这正是判词带统计限制的意义。"

## S8 从评到治（60 秒）

**口播**：
"别的跑分工具出完分数就结束了，这个系统继续往下走两步。第一步，定位到具体哪条规则有害：把 Skill 拆成一条条规则，对照 trace 排弊端榜——榜首'complete-phases-in-order'，四阶段仪式挤占交付；'no-fix-without-root-cause'，根因长论文加零分补丁；机器排出来的，和我手工挖 trace 挖出来的死因一致。第二步，有依据地改：砍掉仪式，留下干货，原文 8.8K 字压到 3.7K，一键送回原流水线同池对照。题目的闭环——定位失效、有依据修改、再验证——在界面上就是两个按钮。还有一条纪律：辅助 LLM 的所有结论带 κ 水印，一致率不到 0.7 不许进定量。我的第一版归因器 κ 等于 0.152，被自己定的规则拦在门外。"

【锚点】弊端榜与一致性：sysdbg analysis + 手工尸检对照记录；8.8K→3.7K：sysdbg-improved SKILL.md；κ=0.152：κ 校准 20 卡结果（门槛 0.7）。
【接招】"LLM 归因不就是幻觉吗？"→"所以给它设了一致性考试，κ≥0.7 才许当法官，不够格就老实当侦探——结论全部带'待复核'水印。"

## S9 证据页（60 秒）

**口播**：
"证据页，读法在页面上。pool-v3 虚构约定池：三套模型先验中不存在的约定——流处理命名、数据库查询语法、部署清单格式，都是我们亲手编的，互联网上一个字都没有。三个臂：A0 不加载，A0p 加载等长无关文档——菜谱，A1f 加载真约定。看这张图：每个族里，两根灰柱几乎一样高——裸考和吃菜谱没区别，排除了'多读几千字就有用'；红柱显著高——真约定才有用。Δ 对安慰剂，正零点三六到正零点六八，三族独立复现。右边是真实任务库的成绩单：真实开源仓库挖了 146 个候选，逐测试过滤只剩 37 个合格，合格率 25%；带内题家族七个 run 稳在 0.67——模型每次修对两处、漏掉同一处，这是稳定的能力边界测量。"
