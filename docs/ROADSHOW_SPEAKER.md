# 路演台词稿（15+4 分钟）
> 配合 ROADSHOW.md 使用。每段：时长 / 台词骨架（口语，可直接念）/ 评委可能反应 / 过渡句。
> 原则：每 90 秒必须有一个"决策点"落地；数字只在被问时展开，不主动念经。

---

## ① 开场定位（0:00–0:40）

"题目问了一个特别朴素的问题：这个 Skill 到底有没有用？我写 Skill 只要十分钟，但判断它有没有用，行业里基本靠'俺寻思'——几次成功的截图、'加上好像不容易出错了'。
我这周做了一个评测体系来回答这个问题。今天不讲功能清单，讲 **25 个设计决策里最关键的十几个**——每个我都告诉你：当时面对什么选择、为什么这么选、不这么选的代价。最后你会发现，这个体系最特别的地方是它**会自我怀疑**——它一边测 Skill，一边监控'我这个评测本身还可信吗'。"

> 评委反应预期：抬头。如果没有，补一刀："先说结论——Skill 要么递答案，要么收仪式税，取决于内容在不在模型的先验里。这句话是可证伪的，我后面给证据。"

**过渡**："先说判分——因为判分错了，后面全是错的。"

## ② 判分的诚实（0:40–3:00）

**决策 1（机械判分）**：
"第一个决策：判分用不用 LLM？我的答案是**一个都不用**。agent 修完 bug，宿主机跑隐藏 pytest，修复必须过、原功能不许挂，双闸门。
为什么？MT-Bench 那篇判官偏差论文实测了 LLM 判官的四大偏差，其中**冗长偏差对我们这个项目是定向打击**——Skill 臂的 agent 读了几千字文档，产出一定更长，LLM 判官天然偏爱长答案，会系统性抬高'Skill 有用'的假象。我用 LLM 判分，测的就是判官的口味，不是模型的能力。
配套一条物理隔离：**tests 永不进容器**——判分的和答卷的分居。"

**决策 2（四关校验，独立思考高光 #1）**：
"第二个决策来自一次打脸。第一版 6 个任务三臂全满分，数据漂亮得能直接写结论。我收手之前多问了一句：**会不会是题出坏了，不是 Skill 没用？** 于是我给题目立了四道机器生死门——gold 必须满分、错解必须判负、漏改必须有测试盯着、结构完整。结果 6 题毙掉 4 题：**连一行代码没改的死跑都能拿满分**。
对漂亮数据的怀疑，是这个体系的第一条铁律：**造卷的不许看考生答案，阅卷的必须是机器。**"

**决策 3（预登记）**：
"第三个决策是防我自己的：判定规则**先于数据写死**——裸考多少算知识缺口、安慰剂差多少算等价、增益多少算显著，全部预登记。看着结果调阈值是评测的原罪，我先把这条路焊死。"

> 评委若问"规则谁审的"："规则公开在 MATRIX_TIERS 里，报告页用户可见——判定不是黑盒。"

**过渡**："判分诚实了，下一个问题：怎么证明增益是 Skill 的功劳？"

## ③ 对照与消融（3:00–5:00）

**决策 4（安慰剂臂，最锋利的一张牌）**：
"直接对比'加载 vs 不加载'有个混淆变量：**多塞几千字进上下文本身就有效应**。所以我有三臂——不加载、加载安慰剂（等长菜谱文档）、加载真 Skill。SkillsBench 八千多个 trial 没做这个臂，他们所有正增益里有多少是'多读了几千字'效应，永远说不清。
我的实测：三个虚构约定族，安慰剂 0.32~0.46 ≡ 裸考 0.20~0.46（预登记容差内），真 Skill 0.82~1.00。**Δ+0.36 到 +0.68，是安慰剂校正过的增益。**"

**决策 5（A1f 与 A1-auto 分离）**：
"官方 Skill 是渐进披露——模型想不想得起用它，和用了有没有效，是两个独立问题。强制注入测内容上限，自主触发测现实价值。这里我自曝一条：A1-auto 目前只在天花板池验证过机制，还没在有效池测过——这是待办，不藏。"

**决策 6（配对符号）**：
"统计上不看池均分——难度混杂会淹没问题。逐任务配对算符号，抗混杂，还天然支持'哪类任务受益'的下钻。成本独立成维，token 和轮次双指标——实测 TDD 的仪式开销 token 只涨 12%，轮次涨 45%，单看 token 会漏报。"

**过渡**："方法论有了，接下来是工程——2400 个 run 怎么不出事故。"

## ④ 工程的可靠（5:00–7:30）

**决策 7（沙箱）**：
"pool-v3 第一批，裸跑的 agent 一个 `find /` 直接读到了宿主机上的答案文件，整批作废。所以每个 run 一个一次性容器，文件系统里只有 /repo 和 /skill。这不是'理论上安全'——51 个确认批 run 做了越界审计，**零命中**。"

**决策 8（渠道协议，独立思考高光 #2）**：
"这次差点出大事。两批 45 个 run 全部零编辑零分，我差点报'注入后能力归零'。挖 trace 发现是中转站降级——空响应、400、403，**能力结论其实是基建死尸**。
赔偿是四件套：跑批前渠道探测，down 熔断一个 run 都不烧；每条 run 记 usage，**usage=0 的死跑是基建失败剔除补跑，usage>0 的无编辑是合法结局**——这条二分线是 45 个 run 的命换的；死跑自动串行补跑；每条结论强制披露渠道健康度。"

**决策 9+10（env 轨与伪影）**：
"每个 run 记环境快照——驱动、模型、镜像 digest。我们走二手中转站，模型别名后面是什么会漂移，没有 env 轨三个月后的复现就是空话。另外撞 maxTokens 顶的死跑单独标记——那是配额的错，不是模型的错。"

**过渡**："工程稳了，系统开始出判定。然后它差点冤枉了一个好人。"

## ⑤ 判定的智慧（7:30–10:00）

**决策 12（天花板检测，独立思考高光 #3，重点讲）**：
"GitHub 高星的 systematic-debugging 进来，分诊 0/6 零信号。但注意：6 个题**双臂全满分**。这时候'零增益'和'池子测不出'是两种东西——直接判出局就是冤案。
所以系统有天花板检测：A0 满分的任务超三分之二，'出局'罪名不成立，自动进**决定性模式**——换带头的难题再上，裸考做不对的题，读了文档还做不对，才算饱和。
结果这个高星 Skill 在带头题上现形了：裸考 4 个满分，读了文档均分 0.42——**它不是没用，是有害**。"

**决策 13+14（阈值校准与污染探针）**：
"决策树的阈值也不是拍的。TDD 首跑 0/6 加成本 1.57 倍，旧规则把它路由到'模糊'——零增益时成本异常是更坏的出局，当天修。
还有人问过我：满分是不是模型背过题？我做了一个污染探针——把满分任务的标识符全部改名，行为等价扰动，模型照样满分。**天花板是真能力，不是背题**——所以换池血要换更难的形态，不是换题。"

**过渡**："到这儿为止，这是个很好的评测系统。但题目要的比评测多一句：定位失效、有依据地改、再验证。这就是从评到治。"

## ⑥ 从评到治（10:00–12:30，产品灵魂，放慢）

**决策 15（弊端定位）**：
"别的跑分工具到判定就结束了。这个系统继续往下挖：**哪条规则最有害**。辅助 LLM 把 Skill 拆成独立规则，结合判定数据和 trace 行为叙事按弊端排序——每条带证据，不带感觉。
systematic-debugging 的机器归因榜首：`complete-phases-in-order`，必须按顺序走完四阶段；第二：`no-fix-without-root-cause`，修之前必须完成根因调查。**这和我手工挖 trace 挖出的死因一模一样**——那个 0 分的 run，agent 严格走完四阶段，写了篇漂亮的根因分析，自信宣布 All pass，隐藏测试 0/3。流程给了它'我验证过了'的底气，没给它'验证得对不对'的能力。"

**决策 16（κ 门）**：
"LLM 参与归因可以，但得先考资格证：机器判官和人裁判的一致率 κ 不到 0.7，阳性结论全部打'待复核'水印，一票不进定量。我的 v1 归因器 κ=0.152，被我自己拦在门外——拦它的规则也是我自己定的。"

**决策 17（改进再验证）**：
"最后闭环：改进版自动生成——砍仪式留干货，8.8K 压到 3.7K——一键送回流水线，同池对照。**题目那句'有依据地修改，再用评测验证修改有效'，在界面上就是两个按钮。**"

**过渡**："最后两分钟，产品化和边界。"

## ⑦ 产品工程 + 边界（12:30–14:30）

"产品层三个用户主权：跑前选档——成本是用户的钱；随时停止——旗标加进程树双保险；全程状态机直播——评测是异步的，用户必须知道跑到哪一步。
边界我主动报五条：单模型单语言单任务域；归因器 fresh κ 还没复标；自主触发臂没在有效池测过；池对当前模型已 92% 天花板；成本是 token 不是钱。**评测别人的体系，得先经得起被评测。**"

## ⑧ 收尾（14:30–15:00）

"总结成一句话：这个体系回答的不是'Skill 有没有用'，而是'**在什么边界内有用、代价是什么、哪里失效、怎么改**'——而且它对自己的效度也用同样的标准审判。演示四分钟，我们直接看。"
